# 002-fix — GitHub trending without the stargazers API

## What failed
A live dry-run collect (with a valid GITHUB_TOKEN) returned **0 GitHub trending candidates**. GitHub no longer lists stargazers: `GET /repos/{owner}/{repo}/stargazers` returns 404 for every repo (also `octocat/Hello-World`, `anthropics/claude-code`, page 1, with or without `application/vnd.github.star+json`), 401 unauthenticated, and GraphQL `stargazers` reports `totalCount: 0`. Per-star timestamps are not available any more, so stars gained must come from star-count snapshots.

## Change
1. In `weekly_diff/collectors/github_trending.py`, remove all stargazer-page logic. Weekly gain is now:
   - **New repos** (`created_at` ≥ window start): `stars_gained = stargazers_count` (every star arrived this week). Set `extra.gain_method = "new"`.
   - **Older repos**: `stars_gained = current − snapshot`, using the snapshot in `data/stars.json` whose age is closest to 7 days within 5–9 days (`snapshot_min_days` / `snapshot_max_days`). Set `extra.gain_method = "snapshot"` and `extra.gain_since` (snapshot date).
   - Neither available → skip the repo quietly (debug log only, not a "source failed" warning; one summary info line with the count skipped).
2. `data/stars.json` becomes a history: `{"version": 1, "repos": {"owner/name": [{"at": iso, "stars": n}, ...]}}`, newest last, at most 6 snapshots per repo, repos not seen for 30 days pruned. Read the old flat format if present. On every non-dry-run collect, record the current `stargazers_count` for **all** unique repos returned by the search queries (search results already include counts; no extra API calls). Never write it in dry-run.
3. Pre-rank and `candidates` limit: still applied, but now after gains are known: rank by `stars_gained` desc and keep the top `candidates`.
4. Remove the now-unused config keys `stargazers_per_page`, `last_page_limit`, `max_stargazer_pages`, `min_age_days` (if only used for the old method) from `config.yaml`, `tests/fixtures/config.yaml` and `weekly_diff/config.py`. Keep everything else.
5. Tests: replace stargazer tests with: new repo gain = total stars; snapshot gain picks the snapshot closest to 7 days within 5–9; too-old/too-new snapshot → skipped; old flat format still read; history capped at 6 and pruned after 30 days; dry-run leaves `data/stars.json` unchanged; ranking by gain, not total stars.
