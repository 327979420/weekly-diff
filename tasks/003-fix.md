# 003-fix — Anthropic structured-output schema and error detail

## What failed
The first real GitHub Actions dry run collected 122 candidates, then the first scoring call failed: `POST https://api.anthropic.com/v1/messages "HTTP/1.1 400 Bad Request"` → `ERROR: Anthropic API status error`.
Anthropic structured outputs (`output_config.format` with `json_schema`) do **not** support: numerical constraints (`minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`), string constraints (`minLength`, `maxLength`, `pattern`), and complex array constraints (`minItems` other than 0 or 1, `maxItems`, `uniqueItems`). Our schemas use `'score': {'type': 'integer', 'minimum': 0, 'maximum': 10}` (weekly_diff/score.py) and `'minItems': 3, 'maxItems': 3` (weekly_diff/sixty.py). Raw `messages.create` sends them as-is, so the API rejects the request.

## Change
1. In `weekly_diff/llm/anthropic_client.py` (or a helper in `weekly_diff/llm/base.py` used only by it), sanitise the schema before sending: recursively remove the unsupported keywords above (keep `minItems` only when 0 or 1), after `strict_schema`. Keep the full schema for the OpenAI client.
2. Keep the constraints enforced client-side: after parsing, validate the response against the **original** schema's numeric, length and item-count limits (a small validator in `weekly_diff/llm/base.py`; no new dependency). On violation raise `LLMError("response did not match schema: <field>")` so the existing one-retry logic applies. Callers that already clamp or check (score range, 3 bullets) keep doing so.
3. Better errors without leaking anything: for `anthropic.APIStatusError` (and the OpenAI equivalent) include the HTTP status, the API error type and the API error message (from the response body, truncated to 300 chars, passed through `redact`) in the `LLMError` text, e.g. `Anthropic API error 400 invalid_request_error: <message>`. Never include the request body, prompt, headers or key.
4. Tests: the payload sent to the mocked Anthropic client contains none of the unsupported keywords (check score and sixty schemas); a response with `score: 14` or 2 bullets raises `LLMError` (then retry path); a mocked 400 with an error body produces an `LLMError` containing status, type and message but not the API key from env.
