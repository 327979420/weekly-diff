# 003-fix (round 2) — LLM request timeout

## What failed
Second GitHub Actions dry run: the first scoring batch succeeded (`LLM model=claude-haiku-5-5 input_tokens=6659 output_tokens=5361`), the second batch failed after ~61 s with `ERROR: Anthropic connection error`. Both LLM clients are built with `timeout=cfg.sources.timeout_seconds` (20 s, meant for web scraping) and `max_retries=cfg.sources.retries` (2), so a scoring call that takes longer than 20 s times out three times.

## Change
1. Add `llm.timeout_seconds` (default and config value **180**) and `llm.max_retries` (config value **2**) to `config.yaml`, `tests/fixtures/config.yaml` and `weekly_diff/config.py` (validated: positive numbers).
2. Use them in both `weekly_diff/llm/anthropic_client.py` and `weekly_diff/llm/openai_client.py` instead of the `sources.*` values.
3. Map timeouts clearly: `anthropic.APITimeoutError` / `openai.APITimeoutError` → `LLMError("Anthropic request timed out after <n>s")` (resp. OpenAI), caught before the connection-error branch.
4. Log the duration of each LLM call next to the token usage line.
5. Tests: clients are constructed with the llm timeout and retries; a mocked timeout produces the timeout message.
